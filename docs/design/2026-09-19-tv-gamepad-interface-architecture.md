# Архитектура интерфейса AudioSwitcher для TV и геймпада

Дата: 19 сентября 2026 года.

## Выбранный вариант

Для AudioSwitcher предлагаются три плоских рабочих раздела:

**Управление → Запущенные → Для запуска**

Настройки не являются четвёртым разделом. Они открываются отдельной кнопкой геймпада как overlay. Текущий родительский раздел «Программы» удаляется, а его подразделы «Запущенные» и «Для запуска» становятся самостоятельными разделами верхнего уровня.

Это не структура PS5: здесь нет домашней карусели, уровней библиотеки или системного control center. Архитектура построена вокруг трёх основных задач AudioSwitcher.

Основное предположение: переключение устройств, перенос и запуск приложений — ежедневные TV-сценарии; редактирование каталога и настроек выполняется реже.

## 1. App Shell

Оболочка состоит из четырёх устойчивых областей.

### Section Bar

- «Управление»;
- «Запущенные»;
- «Для запуска»;
- переключение через LB/RB;
- панель не входит в обычную D-pad-навигацию контента.

### Screen Host

- Одновременно отображается только один полноценный экран.
- Старый список не рисуется под экраном действий или редактором.

### Feedback Region

- Показывает только активную операцию, полезный результат или ошибку.
- Постоянное сообщение «Готово» не отображается.
- Подробности ошибки доступны с геймпада.

### Command Hint Bar

- Показывает только доступные команды текущего контекста.
- Сохраняет постоянную высоту, чтобы компоновка не прыгала.
- Подсказки могут быть кликабельными мышью, но не входят в D-pad-маршрут.

Поверх оболочки может существовать только один overlay. Стек из нескольких модальных карточек не используется.

## 2. Основные разделы

### Управление

Главный и стартовый раздел:

- текущее устройство вывода звука;
- текущий главный монитор;
- быстрый вход в соответствующий выбор.

### Запущенные

Самостоятельный список приложений с окнами:

- название приложения;
- отличительный заголовок окна для одинаковых экземпляров;
- экран и количество окон;
- признак отсутствия ответа;
- перенос и закрытие доступны прямо из списка.

### Для запуска

Самостоятельный пользовательский каталог:

- запуск программы, ярлыка или ссылки;
- редактирование выбранной записи;
- добавление новой записи;
- понятное пустое состояние с явным действием.

### Настройки

Настройки не являются постоянным рабочим разделом. Они открываются кнопкой Menu/Start из корневых экранов. Пока настройка одна, отдельная вкладка неоправданна.

## 3. Главный экран «Управление»

Структура сверху вниз:

1. Section Bar.
2. Строка «Вывод звука»:
   - текущее устройство;
   - статус «Активно»;
   - A открывает выбор устройства.
3. Строка «Главный экран»:
   - название и краткие сведения о мониторе;
   - статус «Главный»;
   - A открывает выбор монитора.
4. Контекстный результат последней операции — только если он полезен.
5. Command Hint Bar:
   - `A Выбрать`;
   - `LB/RB Раздел`;
   - `Menu Настройки`;
   - `B Закрыть`.

Весь ряд является одним focus target. Внутри ряда нет отдельных мелких кнопок.

## 4. Отдельные экраны и overlay/modal

| Функция | Представление | Причина |
| --- | --- | --- |
| Управление | Отдельный экран | Стартовая поверхность |
| Запущенные приложения | Отдельный экран | Нужна максимальная высота списка |
| Каталог запуска | Отдельный экран | Равноправный ежедневный сценарий |
| Выбор окна приложения | Дочерний экран | Требуется сравнивать несколько окон |
| Редактор записи | Дочерний экран | Поля, ввод текста, сохранение и ошибки |
| Выбор аудиоустройства | Overlay-пикер | Короткий локальный выбор |
| Выбор главного монитора | Overlay-пикер | Та же модель, что для звука |
| Настройки | Overlay-панель | Редкий сценарий и мало параметров |
| Ошибка и подробности | Overlay | Не должны уводить в отдельный раздел |
| Завершение приложения | Modal confirmation | Разрушительное действие |
| Удаление записи | Modal confirmation | Разрушительное действие |
| Отмена несохранённых изменений | Modal confirmation | Защита введённых данных |
| Прогресс операции | Inline busy-state | Не требует отдельного диалога |

Отдельное универсальное меню действий для приложения не используется.

## 5. Навигация

- LB/RB циклически переключают три корневых раздела.
- D-pad вверх/вниз двигает фокус только внутри текущего контента.
- D-pad влево/вправо не переключает разделы и не выполняет скрытых действий.
- A выполняет основное действие выбранного объекта.
- B закрывает текущий слой или возвращает на один шаг.
- Из «Запущенных» и «Для запуска» B возвращает в «Управление».
- Из «Управления» B закрывает AudioSwitcher.
- На дочерних экранах LB/RB временно не переключают разделы: сначала нужно завершить или отменить текущий сценарий.
- При возврате восстанавливаются выбранная запись и позиция прокрутки.

Максимальная глубина:

`Корневой экран → дочерний экран → одно подтверждение`

## 7. Focus navigation

Focus state означает только одно: **что произойдёт при нажатии A**.

- Фокус охватывает всю строку.
- Активное устройство и фокус не используют одинаковое состояние:
  - focus — внешний контур;
  - системное состояние — подпись «Активно» или «Главный».
- При открытии пикера фокус ставится на текущее активное значение.
- При подтверждении разрушительной операции начальный фокус всегда находится на «Отмена».
- После успешного действия фокус возвращается к исходному объекту.
- После удаления выбирается ближайшая оставшаяся запись.
- Обновление списков сохраняет выбор по стабильному идентификатору.
- Вертикальные списки не зацикливаются.
- Аналоговый стик использует dead zone и контролируемый repeat.
- A/B/X/Y срабатывают один раз до отпускания.
- Фон overlay не получает фокус.
- Focus state остаётся различимым при высокой контрастности и увеличении текста.

## 8. Назначение кнопок геймпада

| Кнопка | Назначение |
| --- | --- |
| D-pad / левый стик | Навигация по текущему списку |
| A | Основное действие |
| B | Назад / отмена; закрыть приложение только из «Управления» |
| LB / RB | Предыдущий / следующий корневой раздел |
| X | Вторичное действие выбранного объекта |
| Y | Создать новую запись; в редакторе — сохранить |
| Menu / Start | Настройки |
| View / Select | Подробности текущей ошибки, если они есть |

Контекст для X:

- «Запущенные» — закрыть выбранное приложение;
- «Для запуска» — редактировать выбранную запись;
- редактор существующей записи — удалить через подтверждение.

В Command Hint Bar всегда показывается фактическое назначение X/Y. Скрытых комбинаций нет.

## 9. Основные user flows

### Переключить звук

`Управление → строка звука → A → выбрать устройство → A`

Пикер закрывается после успеха. При ошибке остаётся открыт, причина показана рядом.

### Выбрать главный монитор

`Управление → главный экран → A → выбрать монитор → A`

После применения AudioSwitcher корректирует своё положение и возвращает фокус на строку монитора.

### Перенести приложение

`Запущенные → выбрать приложение → A`

- Одно окно — перенос сразу.
- Несколько окон — открывается отдельный экран выбора окна.
- После переноса выполняется выбранное в настройках поведение.

### Закрыть приложение

`Запущенные → выбрать приложение → X → подтверждение`

Вопрос содержит точное имя экземпляра. Начальный выбор — «Отмена».

### Запустить программу

`Для запуска → выбрать запись → A`

Промежуточное меню действий не открывается.

### Добавить запись

`Для запуска → Y → редактор → Y сохранить`

Редактор управляется через D-pad/A/B. Текстовый ввод может использовать системную экранную или обычную клавиатуру.

### Изменить или удалить запись

`Для запуска → X → редактор`

Удаление доступно как вторичное действие и всегда требует подтверждения.

### Изменить поведение переноса

`Menu → Настройки`

Вместо неоднозначного toggle используются два явных варианта:

- «Остаться в AudioSwitcher»;
- «Переключиться в приложение и закрыть AudioSwitcher».

## 10. Что убрать, объединить и упростить

### Убрать

- родительский раздел «Программы»;
- вложенные переключатели «Запущенные / Для запуска»;
- универсальные панели действий после выбора приложения;
- постоянное сообщение «Готово»;
- переключение разделов через D-pad влево/вправо;
- многозначную кнопку Y для каталога, подробностей и сохранения;
- глобальные footer-кнопки «Каталог / Сохранить / Назад», меняющие смысл;
- технические подробности, доступные только в tooltip;
- отображение старого списка под новым экраном.

### Объединить

- выбор аудио и монитора в общий `ChoiceOverlay`;
- подтверждения завершения, удаления и сброса в один `ConfirmationDialog`;
- обработку геймпада, клавиатуры и мыши через семантические команды;
- все списки в общий focus-aware list;
- статус, прогресс и ошибку в единую feedback-модель.

### Упростить

- A на запущенном приложении сразу означает перенос;
- A на записи каталога сразу означает запуск;
- X выполняет одно очевидное вторичное действие;
- настройки убираются из постоянной навигации;
- аварийная команда «Сбросить каталог» появляется только при ошибке каталога;
- верхняя навигация содержит три пункта;
- настройка поведения переноса представлена двумя понятными вариантами.

## Компактное дерево экранов

```text
AudioSwitcher
├── Управление
│   ├── Вывод звука
│   │   └── [overlay] Выбор устройства
│   └── Главный экран
│       └── [overlay] Выбор монитора
├── Запущенные
│   ├── A: перенести
│   │   └── Выбор окна
│   └── X: закрыть
│       └── [modal] Подтверждение
├── Для запуска
│   ├── A: запустить
│   ├── X: редактировать
│   │   └── Редактор записи
│   │       └── [modal] Удалить / отменить изменения
│   └── Y: добавить
│       └── Редактор записи
├── [overlay] Настройки
└── [overlay] Подробности ошибки
```

Итоговая модель: три корневых раздела, максимум один дочерний экран и один активный overlay.
