# Управление программами — проект и план реализации

**Статус:** согласован Денисом; реализация завершена 18 сентября 2026 года. Результаты и ограничения — в docs/VERIFICATION.md.
**Ветка:** `codex/program-management`, создана от `master`, исходный коммит `cf7b20f`.
**Цель:** перемещать окно выбранной программы на текущий главный экран, принудительно завершать выбранную программу и открывать программы из подготовленного пользователем списка.
**Архитектура:** отдельный WPF-раздел и небольшие сервисы перечисления окон, перемещения, завершения процесса, запуска и хранения каталога. Правила фильтрации, расчёт размещения и состояние навигации отделены от Windows API.
**Стек:** существующие C# / .NET 10 / WPF, Win32 через P/Invoke, System.Diagnostics, System.Text.Json; без сторонних NuGet-пакетов.

Документ совмещает согласованный дизайн и этапы разработки. Каталог вынесен в Core/LaunchModels.cs; нативные объявления — в Platform/ProgramNative.cs. Для изолированных проверок добавлены проекты CatalogChecks и ProgramFixture.

## 1. Границы задачи

- Windows 10/11 x64, портативный самодостаточный EXE, запуск с правами текущего пользователя.
- Русский интерфейс в существующем оформлении, мышь, клавиатура и XInput-геймпад.
- Существующие разделы «Звук» и «Мониторы» сохраняют своё поведение.
- Новый верхний раздел «Программы» содержит два визуально раздельных списка: «Запущенные» и «Для запуска». По умолчанию открывается «Запущенные».
- Список запуска пользователь создаёт заранее. Каталог не ограничивает обнаружение запущенных приложений: игра видна, даже если её нет в каталоге.
- Перемещение использует главный экран на момент команды. Пользователь заранее назначает ТВ главным через существующий раздел «Мониторы».
- Не добавляем службы, резидентную работу, автоматическое повышение прав, инъекции в игры, горячие клавиши вызова или автоматическое обнаружение установленных игр.

## 2. Выбор подхода

| Подход | Преимущества | Ограничения |
| --- | --- | --- |
| **Рекомендуемый: автоматически обнаруживать пользовательские окна + отдельный ручной каталог запуска** | Не нужно заранее добавлять зависшую игру; списки имеют разные задачи | Не охватывает фоновые приложения без окон; требуется фильтрация оболочки Windows |
| Только вручную добавленные программы для обоих списков | Максимальный контроль состава | Нельзя завершить или переместить ещё не добавленную игру; сложнее сопоставлять ярлык лаунчера с процессом игры |
| Все процессы текущего пользователя | Видны фоновые процессы | Системные и вспомогательные процессы создают путаницу и противоречат запросу |

Первую версию строим по рекомендуемому подходу. «Пользовательские программы» здесь означают приложения с доступным пользователю окном, включая свёрнутые и зависшие. Это определение согласовано; оно не означает список всех установленных программ или всех процессов пользователя.

## 3. Список «Запущенные»

### Состав и обновление

- Перечислять верхнеуровневые окна через EnumWindows, получать владельца через GetWindowThreadProcessId.
- Оставлять окна текущей сессии и текущего пользователя: обычные пользовательские окна и свёрнутые окна. Скрытые, DWM-cloaked и WS_EX_TOOLWINDOW исключать; учитывать WS_EX_APPWINDOW и отношения владельца.
- Исключать AudioSwitcher, рабочий стол, панель задач, оболочку Start/Search и системные хосты. Не исключать Explorer целиком: обычные окна проводника остаются пользовательскими приложениями.
- Проверку системных хостов строить по сочетанию класса окна и проверенной системной исполняемой программы, а не только по имени процесса. Недостаточно запрещать всё из Windows или разрешать всё вне Windows.
- Не отбрасывать зависшее окно из-за отсутствия ответа и не применять безусловный фильтр «непустой заголовок»: для безымянного окна использовать имя исполняемой программы.
- Одна строка на процесс с одним подходящим окном. Если у процесса несколько подходящих окон, под строкой показать их количество; перед перемещением предложить выбор конкретного окна. Завершение процесса закроет все его окна.
- Разные экземпляры одной программы отображать отдельно. По замечанию Дениса название строки — описание EXE, затем имя продукта, при отсутствии метаданных — имя файла; заголовки окон доступны при выборе конкретного окна для переноса. PID не является основным пользовательским названием.
- Детали строки: текущий экран и количество окон; признак «Не отвечает» — вспомогательный, он не обязателен для команды завершения.
- Обновление каждые 3 секунды только при открытом списке, F5 — вручную. Выполнять сбор снимка вне UI-потока, не запускать два обновления одновременно.
- Сохранять выбор по экземпляру процесса, а не по имени; ключ экземпляра включает PID и время создания процесса. Для окна дополнительно хранить HWND.
- При закрытии окна между обновлениями и нажатием команды выводить «Программа уже закрыта» и обновлять список.
- Если Windows не позволяет проверить владельца/экземпляр процесса, не предоставлять управление непроверенной целью. Для проверенного приложения с ограничением на конкретную команду показывать понятный отказ.

### Действия

Выбор строки сам по себе ничего не выполняет. A / Enter / двойной щелчок открывает панель действий:

1. «На главный экран» — первоначально выбранное действие.
2. «Завершить принудительно».

Для нескольких окон перед первым действием открывается выбор окна. Для второго — подтверждение с названием: «Завершить [программа]? Несохранённые данные будут потеряны». По умолчанию выбран «Отмена». A, удерживаемая при открытии подтверждения, не должна подтверждать завершение без отпускания и нового нажатия.

Принудительно завершать только выбранный процесс, без дерева дочерних процессов и без поиска по совпадению имени EXE. Лаунчер, соседние экземпляры и другие программы не затрагивать. Это не гарантирует завершение всех вспомогательных процессов многопроцессного приложения; управление деревом процессов не входит в первую версию.

Перед командой заново проверять экземпляр процесса и принадлежность HWND. Для завершения использовать открытый и проверенный дескриптор процесса, не выполнять повторное обращение только по старому PID. Если цель больше не совпадает, команда отменяется.

## 4. Перемещение на главный экран

- Отдельный сервис для чужих окон; существующий WindowPlacement.Center остаётся предназначенным для окна AudioSwitcher.
- Перед операцией запросить актуальную топологию и текущий главный монитор через Windows API; не опираться на ранее выбранный дисплей или кэш WPF.
- Обычное окно центрировать в рабочей области главного экрана. Сохранять его размер, если он помещается; слишком большое обычное окно вписывать в рабочую область с учётом DPI и минимального размера приложения. Если ограничения окна мешают вписыванию, сообщать о неполном результате.
- Развёрнутое окно переводить на целевой экран с сохранением развёрнутого состояния; свёрнутое восстанавливать на целевом экране. Явно проверить правильность screen/workspace coordinates для WINDOWPLACEMENT и разные масштабы DPI.
- Окно без рамки, которое до операции покрывало исходный монитор, размещать по полным границам целевого монитора, включая размер ТВ. Стили окна и видеорежим игры не менять.
- Не менять порядок окон и не отнимать фокус у AudioSwitcher во время команды.
- Использовать асинхронные флаги Windows API и ограниченное ожидание результата вне UI-потока. После реакции приложения повторно проверить принадлежность окна целевому монитору; «Готово» показывать только при подтверждённом переносе.
- Предлагаемый предел ожидания перемещения — 2 секунды. Если окно не отреагировало или вернулось обратно: «Не удалось перенести окно. Попробуйте оконный режим без рамки».
- При отключении ТВ во время операции заново проверить цель; не продолжать перемещение по устаревшим координатам.
- Эксклюзивный полноэкранный режим не гарантируется. Некоторые игры самостоятельно выбирают дисплей или восстанавливают свои координаты: нужна проверка на используемых Денисом играх. Зависшему окну перенос может быть недоступен, завершение процесса от этого не зависит.

## 5. Список «Для запуска»

- Содержит только записи, явно добавленные пользователем. Запущенные процессы автоматически сюда не добавляются.
- Действие записи — «Открыть». Действий перемещения и завершения здесь нет.
- «Добавить программу» открывает выбор EXE или ярлыка .lnk/.url; поддержать штатные игровые ярлыки, включая запуск через зарегистрированный игровой лаунчер.
- Карточка записи: отображаемое название, тип цели, путь. Для EXE можно задать аргументы и рабочую папку; аргументы хранить отдельно от пути. Аргументы ярлыков берутся из самого ярлыка.
- Для .url читать цель и разрешать https/http, steam и com.epicgames.launcher; остальные схемы отклонять с пояснением. Не исполнять произвольные cmd/PowerShell-команды из каталога. .lnk/.exe остаются явно выбранными пользователем локальными целями.
- Возможность переименовать, изменить цель/параметры и удалить запись. Удаление записи не удаляет приложение или файл ярлыка.
- Запуск через ProcessStartInfo с UseShellExecute = true, без сборки строк для командной оболочки.
- Результат успешного ShellExecute — «Команда запуска отправлена», а не утверждение, что игра уже загрузилась. Запись не переносится в другой список; запущенное окно появится при обнаружении.
- Если программа уже работает, явная команда запуска всё равно передаётся цели; единственный экземпляр или повторный запуск определяет само приложение/лаунчер. Не сопоставлять игру с ярлыком по имени.
- Отсутствующий файл, рабочая папка или незарегистрированный протокол дают ошибку в статусе. Запись сохраняется для исправления.
- Первичное заполнение и редактирование каталога рассчитаны на клавиатуру/мышь; выбор и открытие сохранённых записей полностью доступны с геймпада.

### Хранение

Файл `%LOCALAPPDATA%\AudioSwitcher\programs.json`, схема версии 1. Пример структуры:

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "id": "6b84df17-3d07-41db-ab99-cbd772246d73",
      "name": "Моя игра",
      "kind": "Shortcut",
      "target": "C:\\Games\\MyGame.lnk",
      "arguments": "",
      "workingDirectory": ""
    }
  ]
}
```

Это новые локальные настройки: текущий README о полном отсутствии настроек потребуется обновить. Файл создаётся при первом сохранении каталога. EXE остаётся портативным, а каталог привязан к пользователю Windows; перенос каталога между компьютерами вручную, пути могут требовать исправления.

Сохранение через временный файл в той же папке и атомарную замену. При повреждённом JSON показать ошибку, оставить исходный файл без перезаписи и отключить сохранение до явного сброса пользователем с сохранением копии повреждённого файла. Неизвестную будущую версию схемы не перезаписывать. При отказе записи не сообщать об успешном сохранении и не терять действующий каталог.

## 6. Навигация и состояния интерфейса

- Верхние разделы: «Звук», «Мониторы», «Программы». LB/RB переключают предыдущий/следующий раздел; клавиши ←/→ на основном экране сохраняют эту функцию.
- В «Программах» видны переключатели «Запущенные» и «Для запуска», активный список отмечен. X на геймпаде меняет список; клавиатурой/мышью доступны сами переключатели.
- ↑/↓ выбирают строку. A / Enter открывает действия для запущенного приложения или запускает запись каталога.
- Панели действий и подтверждения управляются ↑/↓ и A / Enter; верхнее переключение разделов и X в этих панелях отключены.
- B / Esc сначала отменяет подтверждение или закрывает панель действий. На основном экране, как сейчас, закрывает AudioSwitcher. Подсказки меняются вместе с контекстом.
- В полях редактирования стрелки и Enter обрабатываются формой, а не глобальным управлением разделами. Геймпад не запускает действие основного экрана поверх открытого системного диалога выбора файла.
- Для смены контекста ввода использовать отдельное состояние навигации и переармирование подтверждения: удержание A/Enter не переносится в следующую панель.
- Состояния: загрузка списка, пустой список, нет доступного окна, перемещение, завершение, запуск, успех, отказ в доступе, исчезнувшая цель.
- Во время операции блокировать конфликтующие команды, но оставлять интерфейс отзывчивым. Ожидание завершения процесса ограничить 3 секундами; при тайм-ауте сообщать, что выход пока не подтверждён, и продолжать наблюдение обычным обновлением списка.
- Ошибки показывать коротко в статусе; подробности доступны по существующей модели tooltip. Для нужного действия не полагаться только на tooltip — сообщение об отказе понятно сразу.
- Проверить вкладки и панели при 480×550 и минимальных 340×400, с переносом/компактным расположением вкладок. Большие списки приложений не подставлять в специальную DeviceRowsPanel без оценки её измерения всех строк; использовать отдельный обычный список с подходящей прокруткой.
- Присвоить AutomationId и русские доступные названия переключателям, спискам, действиям и подтверждениям; статус остаётся live region.

## 8. Этапы реализации

### Этап 1. Проверить управление окнами на изолированной программе

- [x] Добавить ProgramFixture: обычное, безрамочное, свёрнутое и развёрнутое окно; несколько окон; режим блокировки оконного потока. Управление фикстурой через аргументы запуска и отдельный канал, не зависящий от её UI-потока.
- [x] Создать ProgramChecks по существующей модели консольных проверок без тестовых пакетов, со ссылкой на основное приложение и обязательным finally для уборки только созданных фикстур.
- [x] Реализовать перечисление и минимальный перенос. Проверить на двух мониторах с разным DPI, что зависшая фикстура не блокирует AudioSwitcher.
- [x] Проверить завершение только одной выбранной фикстуры при двух одинаковых EXE. Второй экземпляр должен остаться жив.
- [x] Зафиксировать фактические ограничения до сборки окончательного интерфейса. Если какая-либо игра не допускает перенос, не обещать поддержку на основании одной фикстуры.

**Результат:** подтверждённая Windows-основа и воспроизводимые проверки собственных процессов.

## 9. Критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| ТВ уже главный; игра открыта на мониторе | Игра видна в «Запущенных»; команда переносит её окно на ТВ; AudioSwitcher не меняет главный монитор |
| Игра/фикстура зависла | Программа остаётся доступна в списке; после отдельного подтверждения завершается выбранный процесс; интерфейс управления отзывчив |
| Два экземпляра одного EXE | Завершение одного не затрагивает второй |
| Программа отсутствует в каталоге запуска | Её пользовательское окно всё равно обнаруживается в «Запущенных» |
| Предварительно добавленный EXE/ярлык | Видно только в «Для запуска»; команда отправляет запуск; каталог сохраняется после закрытия AudioSwitcher |
| Окно закрылось или снимок устарел | Сообщение об исчезнувшей/изменившейся цели; посторонняя цель не получает команду |
| Системные фоновые процессы и служебные окна | Не отображаются как управляемые пользовательские программы |
| Отказ в доступе или игра возвращает своё окно | Понятная ошибка/ограничение, без ложного «Готово» |
| Удержание A/Enter при смене панели | Не запускает повторную команду и не подтверждает завершение |
| Минимальное окно и геймпад | Доступны оба списка, действия, подтверждение и возврат |
| Повреждённые/недоступные настройки | Нет молчаливой перезаписи или ложного подтверждения сохранения |

## 10. Решения для валидации

1. «Запущенные» — автоматически обнаруженные пользовательские окна, включая игры не из каталога; фоновые приложения без окон не показываем.
2. «Для запуска» — отдельный ручной каталог EXE и ярлыков, сохранённый в профиле Windows.
3. Перенос применяется к выбранному окну на текущий главный экран; обычный размер сохраняется по возможности, безрамочное окно на весь монитор подстраивается под ТВ.
4. Принудительное завершение требует отдельного подтверждения и относится только к выбранному процессу, без дочернего дерева.
5. Создание каталога — клавиатура/мышь; ежедневное использование, действия и подтверждение — также геймпад. X переключает два списка.

## 11. Основания технических решений

- [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos): перемещение/размер окна, SWP_ASYNCWINDOWPOS и сохранение фокуса/порядка.
- [SetWindowPlacement](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowplacement): состояние свёрнутого/развёрнутого окна и восстановленные координаты.
- [GetWindowTextW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw): получение заголовка чужого окна без прямого запроса его UI-потоку.
- [DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute): признак DWMWA_CLOAKED для фильтрации недоступных окон.
- [Process.Kill](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.kill): различие принудительного завершения и обычного запроса закрытия; завершение нужно отдельно подтвердить наблюдением.
- [IsWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-iswindow): HWND может быть повторно использован; одной проверки существования недостаточно для идентификации выбранной цели.

Поддержка конкретной игры и качество переноса между разными DPI требуют фактического испытания; документация API не заменяет эту проверку.

## 12. Итог реализации

В версии 1.4.4 исправлена disabled-отрисовка списка окон во время переноса и смягчена проверка геометрии для окон с невидимой рамкой.

В версии 1.4.3 исправлены stale-артефакты списка после переноса: обновление списка выполняется после отрисовки возврата из панели действий. Модальное меню больше не оставляет серую рамку и сохраняет элементы при повторном открытии и закрытии.

В версии 1.4.2 по замечаниям Дениса удалена «Настроить запись»: запись открывает модальное окно «Запустить / Удалить / Редактировать / Отмена» поверх интерфейса. Строки и действия программ реагируют на одиночный щелчок; аппаратная проверка полного пути через интерфейс переносит собственную фикстуру на главный экран. Отдельный сбой конкретной пользовательской программы требует её названия и сообщения результата.

В версии 1.4.1 учтены замечания Дениса: подразделы оформлены текстом без рамок, выбранный отличается цветом; список показывает названия приложений из метаданных EXE вместо заголовков окон.

Все этапы реализованы. Аппаратный перенос проверен на двух доступных мониторах с собственными тестовыми окнами, включая DPI-unaware/system-aware и повторный перенос. Реальные игры и exclusive fullscreen не проверялись. Автоматический выбор файла в нативном диалоге пропущен из-за ограничений среды; свойство DereferenceLinks=false задано явно, фактический запуск собственной .lnk с аргументами проверен отдельно. Переключение системных устройств в этом прогоне не выполнялось; прежние регрессии интерфейса сохранены.
