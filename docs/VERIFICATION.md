# Проверка сборок

## Обновление 1.4.4 — исправление disabled-отрисовки и подтверждения геометрии

Снимок пользователя показал белую область в списке окон во время переноса. Причина — отключение `PanelSurface.IsEnabled`, из-за которого WPF применял системную disabled-отрисовку к строкам. Блокировка теперь выполняется через `IsHitTestVisible=false`, поэтому элементы сохраняют обычную тёмную отрисовку. После переноса панель сначала отрисовывается, затем обновляется источник списка.

Окно Explorer могло фактически переместиться на главный экран, но получить ложный тайм-аут из-за нескольких пикселей невидимой рамки или рабочей области. Проверка результата теперь принимает окно, если оно полностью помещается либо не менее половины его площади пересекает целевую рабочую область; тонкий край за пределами экрана по-прежнему отклоняется. Добавлена чистая регрессия обоих случаев.

WindowChecks: 11 PASS, 0 FAIL, 2 SKIP; чистая логика: 14 PASS; ProgramChecks с переносом собственной фикстуры ранее: 16 PASS. Снимки после переноса и модального окна просмотрены, белая область и серая рамка отсутствуют. Portable-сборка обновлена до 1.4.4.

## Обновление 1.4.3 — стабильное модальное меню и перерисовка списка после переноса

Исправлены два замечания Дениса. После переноса окна AudioSwitcher сначала завершает переход панели и только затем обновляет `ItemsSource` списка. Это устраняет stale-отрисовку выбранной строки, которая оставляла белые пиксели после нативного перемещения окна между мониторами. Снимок `artifacts/ui-programs-after-move.png` после переноса собственной фикстуры не содержит артефактов.

Модальный слой теперь использует фоновую кисть самого приложения вместо полупрозрачного `ContentControl`, поэтому вокруг карточки нет серой рамки. Ограничение высоты карточки не сохраняется между перепривязками визуального дерева. Проверка открывает и закрывает меню пять раз подряд, затем повторно проверяет запуск, редактирование, удаление и отмену; все элементы остаются доступными. Снимки `ui-programs-catalog-modal.png` и `ui-programs-catalog-modal-small.png` просмотрены.

Итог регрессии после исправлений: WindowChecks — 11 PASS, 0 FAIL, 2 SKIP; собственный перенос через интерфейс — PASS; чистая логика — 13 PASS; каталог — 26 PASS. SKIP относится только к автоматизации системного файлового диалога и необязательному изменению главного монитора.

## Исходная сборка 1.0.0

Проверено 17 сентября 2026 года на Windows 11 x64, .NET SDK 10.0.301.

- `dotnet run --project tests/AudioSwitcher.Checks`: 4 проверки пройдены; перенос координат экранов, отказ для отсутствующего экрана, защита от повторного подтверждения, повтор навигации при удержании.
- `dotnet run --project tests/AudioSwitcher.PlatformChecks -- --switch-and-restore`: 6 проверок пройдены. Реально переключены аудиовыход и главный монитор; все три исходные аудиороли, главный монитор, координаты, разрешения и частоты экранов восстановлены и сверены.
- `tests/ui-smoke.ps1` на окончательном portable EXE: 5 проверок пройдены — окно поверх остальных, раздел звука, раздел мониторов, возврат в звук, завершение процесса по Esc. Снимок интерфейса проверен визуально.
- Диагностика окончательного portable EXE: 6 активных аудиовыходов, 2 активных монитора, XInput-геймпад подключён.
- Сборка Release: без ошибок и предупреждений. EXE самодостаточный, один файл размером 64 757 795 байт.

Физические нажатия кнопок геймпада автоматически не эмулировались. Эксклюзивный полноэкранный режим игр не проверялся; для окна поверх игры предусмотрен оконный режим без рамки. Совместимость с Windows 10 заявлена по используемым API и платформе .NET, отдельная проверка на Windows 10 не выполнялась.

Для доступа к видеодрайверу интеграционные проверки запускались вне песочницы. Внутри неё Windows возвращала отказ для CDS_TEST даже на текущих режимах. Также исправлена отдельная ошибка предварительной проверки: CDS_TEST не должен проверять перенос текущего главного экрана отдельно от остальной топологии; видеорежимы проверяются без DM_POSITION, затем все координаты записываются и применяются вместе.
