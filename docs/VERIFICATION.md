## Обновление 1.3.1 — стабильная прокрутка списка

Воспроизведены две причины смещения: виртуализация строк с переносом текста пересчитывала предполагаемую общую высоту в первом проходе (например, с 1878,40 до 1843,60 DIPs), а выбор последнего устройства через ScrollIntoView оставлял 4 DIPs до физического конца списка. Для небольшого списка устройств отключена виртуализация с сохранением пиксельной прокрутки. При выборе первого и последнего устройств применяются границы ScrollViewer; ScrollIntoView используется для внутренних строк, чтобы его отложенный MakeVisible не переопределял прокрутку у границ.

Регрессия до исправления: 2 PASS, 4 FAIL. После исправления `AudioSwitcher.WindowChecks`: Passed: 6, Failed: 0, Skipped: 1. Новые проверки `Stable row geometry and edge scrolling at 480x550`, `480x400`, `340x550`, `340x400` используют 20 устройств разной высоты, проверяют постоянство общей высоты, видимость выбранной строки, два последовательных прохода с одинаковыми смещениями, повторные нажатия на границах и совпадение выбора последнего устройства с прокруткой до конца. Системные настройки эти проверки не меняют.

`build.ps1`: код 0; базовые проверки Passed: 4, Failed: 0, Skipped: 0. Портативный EXE имеет ProductVersion 1.3.1, FileVersion 1.3.1.0; ZIP пересобран. UI Automation на портативном EXE: 7 PASS. Независимый обзор исправления: блокирующих дефектов не найдено. При публикации сохраняется предупреждение NU1900 об отсутствии доступа к api.nuget.org в песочнице; проект не использует сторонние пакеты.

## Обновление 1.2.0 — исправление перемещения и прокрутки

Оба дефекта воспроизведены регрессионными проверками окна: после первого подтверждения окно оставалось на прежнем мониторе, а при прокрутке до конца в окне высотой 550 оставалось 70,7 DIPs пустоты под последней строкой.

Для размещения используются актуальные `MonitorFromPoint`, `GetMonitorInfo` и `SetWindowPos`, без задерживающегося кэша `SystemParameters.WorkArea`. Учитывается DPI целевого монитора и завершающая реакция окна на смену DPI. Список использует пиксельную прокрутку с сохранением виртуализации; после прокрутки остаётся только штатный отступ строки в 5 DIPs.

Кнопки применения и закрытия удалены. Вместо применения показана подсказка A / Enter. Сохраняются двойной щелчок, A на геймпаде, Enter, B на геймпаде и Esc. Сверху остаётся пустая область для перетаскивания.

`AudioSwitcher.WindowChecks`: 3 проверки пройдены. Проверяет нижнюю строку при высоте 550 и 400, а также перемещение после первого подтверждения в обоих направлениях, включая увеличенное до 3600 × 1800 окно. Дополнительно проверяется, что после реакции на DPI окно целиком находится в рабочей области целевого монитора. Проверки запускаются с таким же manifest PerMonitorV2, как у EXE. UI Automation: 7 проверок пройдены — отсутствие кнопок, наличие подсказки, оба раздела, окно поверх остальных и завершение по Esc. Системные настройки после регрессионного переключения восстанавливаются.

## Исходная сборка 1.0.0

Проверено 17 сентября 2026 года на Windows 11 x64, .NET SDK 10.0.301.

- `dotnet run --project tests/AudioSwitcher.Checks`: 4 проверки пройдены; перенос координат экранов, отказ для отсутствующего экрана, защита от повторного подтверждения, повтор навигации при удержании.
- `dotnet run --project tests/AudioSwitcher.PlatformChecks -- --switch-and-restore`: 6 проверок пройдены. Реально переключены аудиовыход и главный монитор; все три исходные аудиороли, главный монитор, координаты, разрешения и частоты экранов восстановлены и сверены.
- `tests/ui-smoke.ps1` на окончательном portable EXE: 5 проверок пройдены — окно поверх остальных, раздел звука, раздел мониторов, возврат в звук, завершение процесса по Esc. Снимок интерфейса проверен визуально.
- Диагностика окончательного portable EXE: 6 активных аудиовыходов, 2 активных монитора, XInput-геймпад подключён.
- Сборка Release: без ошибок и предупреждений. EXE самодостаточный, один файл размером 64 757 795 байт.

Физические нажатия кнопок геймпада автоматически не эмулировались. Эксклюзивный полноэкранный режим игр не проверялся; для окна поверх игры предусмотрен оконный режим без рамки. Совместимость с Windows 10 заявлена по используемым API и платформе .NET, отдельная проверка на Windows 10 не выполнялась.

Для доступа к видеодрайверу интеграционные проверки запускались вне песочницы. Внутри неё Windows возвращала отказ для CDS_TEST даже на текущих режимах. Также исправлена отдельная ошибка предварительной проверки: CDS_TEST не должен проверять перенос текущего главного экрана отдельно от остальной топологии; видеорежимы проверяются без DM_POSITION, затем все координаты записываются и применяются вместе.
