# Project rules

## Testing scope

- Test only to the extent necessary to verify the changes made.
- Do not run the full test suite when a local check of the affected functionality is sufficient.
- Do not repeat successfully completed tests without a specific reason.
- Make at most two attempts to fix the same problem. If the problem persists after two attempts, or there is no clear progress, stop and briefly report the cause and the verification result.
- After a relevant check passes, consider the task complete. Do not continue with additional testing unless it is necessary.
- These testing rules apply unless the user's request explicitly says otherwise.

## Build artifact

- After every change, rebuild the project and provide the user with a link to the resulting `.exe` file.
